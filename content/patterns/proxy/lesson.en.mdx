<Section id="problem">

A property-listing site shows a house, its photos and a floor plan. Each plan is a high-resolution scan, and loading one is slow and heavy. Most visitors never open the plan. Plans of unpublished listings must also stay hidden from everyone who is not an agent. The first version of <Role kind="concrete">ListingPage</Role> does both jobs itself:

<AnnotatedCode
  caption="The first version: the page loads the scan and checks access"
  code={`
public class ListingPage
{
    private readonly ScannedFloorPlan plan;
    private readonly bool published;
    private readonly bool isAgent;

    public ListingPage(string address, bool published, bool isAgent)
    {
        this.published = published;
        this.isAgent = isAgent;
        plan = new ScannedFloorPlan(address);
    }

    public void ShowPlan()
    {
        if (!published && !isAgent)
        {
            Console.WriteLine("Plans are not available");
            return;
        }
        Console.WriteLine(plan.Render());
    }
}
`}
  marks={[
    { line: 3, tone: 'bad' },
    { line: 11, tone: 'bad', badge: '1' },
    { line: 16, tone: 'bad', badge: '2' },
    { line: 18, tone: 'bad' },
    { line: 19, tone: 'bad' },
  ]}
/>

It shows the right plan to the right people, but <Key>the page creates the real scan and guards it at the same time</Key>, and it does both in the wrong place:

<BadgeList tone="bad" count={2}>

1. The scan is loaded when the page is made, whether or not anyone opens the plan. A listing that nobody looks at still pays the full cost of its scan.
2. The access check is in the page, and it comes after the load. A plan that the visitor is not allowed to see has already been loaded by then, and every other page that shows plans has to repeat the check.
3. Opening ten listings loads ten scans, and if the visitor looks at none of them, all ten loads were wasted.
4. The page has two jobs besides showing a plan: deciding when to load, and deciding who may look. A change to either rule means a change to the page.

</BadgeList>

<KeyIdea>

The page should only ask for the plan. Something else, standing where the plan stands, can decide when a <Role kind="concrete">ScannedFloorPlan</Role> is needed and who may see it.

</KeyIdea>

</Section>

The **subject** is <Role kind="contract">IFloorPlan</Role>, with the one method <Role kind="contract">Render</Role>. It is what the page depends on.

The **real subject** is <Role kind="concrete">ScannedFloorPlan</Role>. It does the real work and is expensive to create. It does not know that a proxy exists.

The **proxy** is <Role kind="primary">FloorPlanProxy</Role>. It implements the same <Role kind="contract">IFloorPlan</Role>, so it can go anywhere a floor plan is expected. It holds the address, the rule for who may look, and a `ScannedFloorPlan?` field that starts empty. In `Render` it first checks the rule. If the viewer may look, it creates the scan if there is none yet, and passes the call on. If not, it answers by itself.

The client is <Role kind="concrete">ListingPage</Role>. It holds an <Role kind="contract">IFloorPlan</Role> and calls `Render`. Nothing in the page names the proxy or the scan, so the stand-in can be added or taken away without changing it. Hover or focus a box in the diagram to see its code in the example.

<Section id="example">

The example is the program from the scene, and it ends with the listing that is not open to viewers. Run it and you should see eight lines: `Scans loaded: 0`, then the plan for 12 Elm Street and `Scans loaded: 1`, the same plan again and `Scans loaded: 1`, then `Plans of 9 Mill Lane are not available`, `Scans loaded: 1` and `Scan renders: 2`. The scan was made only when the first plan was shown, and never for the hidden listing.

Then change it. Add a cache. Give <Role kind="primary">FloorPlanProxy</Role> a field `private string? rendered;` and change the last line of its `Render` to `return rendered ??= scan.Render();`. You should see `Scan renders: 1`: the second page call is answered from the proxy's memory, and the scan is not asked again. <Key>A cache is one more thing a proxy can control</Key>, and <Role kind="concrete">ListingPage</Role> and <Role kind="concrete">ScannedFloorPlan</Role> need no change.

<Section id="when-to-use">

Use Proxy when:

<Checklist>
  <Verdict ok><span>an object is <Key>expensive to create</Key> and often not needed, so you want to create it only when it is first used;</span></Verdict>
  <Verdict ok><span>you must <Key>control access</Key> to an object, such as who may use it or when, and the object itself should not carry that rule;</span></Verdict>
  <Verdict ok><span>you want a <Key>local stand-in</Key> that keeps the same interface, for results to remember or for an object that lives somewhere else.</span></Verdict>
  <Verdict ok={false}><span>**Skip it** when there is nothing to control, or when what you want is to add behaviour to the result. Adding behaviour in layers is Decorator, and a proxy for an object that is cheap and open to everyone is only an extra class.</span></Verdict>
</Checklist>

### A lazy value you already use

<Note icon="lightbulb">

In .NET, `Lazy<T>` does the job of the virtual proxy's null check. The value is created the first time `.Value` is read, and not before. `FloorPlanProxy` could hold `new Lazy<ScannedFloorPlan>(() => new ScannedFloorPlan(address))` and use `scan.Value.Render()`. By default `Lazy<T>` is thread-safe (`LazyThreadSafetyMode.ExecutionAndPublication`): if several threads ask at once, one of them runs the factory and the others get that value. The `??=` in the example is not thread-safe, because two threads could both find the field empty and each create a scan.

</Note>

### Pitfalls

<Pitfall title="A proxy that loads in its constructor">

A proxy exists to hold off the load. If it creates the real object when it is made, you have moved the problem and not solved it: the page still loads every scan when the listing opens. Create the real object inside the method that first needs it. A <Role kind="primary">FloorPlanProxy</Role> made for a listing nobody opens should never make a <Role kind="concrete">ScannedFloorPlan</Role>.

<CodePair
  bad={"public class FloorPlanProxy(string address, bool canView) : IFloorPlan\n{\n    private readonly ScannedFloorPlan scan = new(address);   // loads when the proxy is made\n\n    public string Render() =>\n        canView ? scan.Render() : $\"Plans of {address} are not available\";\n}"}
  good={"public class FloorPlanProxy(string address, bool canView) : IFloorPlan\n{\n    private ScannedFloorPlan? scan;\n\n    public string Render()\n    {\n        if (!canView)\n            return $\"Plans of {address} are not available\";\n\n        scan ??= new ScannedFloorPlan(address);   // loads on the first Render\n        return scan.Render();\n    }\n}"}
  badLabel="the scan is loaded at once"
  goodLabel="the scan is loaded on the first Render"
/>

</Pitfall>

<Pitfall title="A proxy that hands out the real object">

The proxy only controls access if every call goes through it. If it returns the real object, or has a public member for it, a client can take it and skip the check. Keep the real object private, and give out only the methods of <Role kind="contract">IFloorPlan</Role>.

<CodePair
  bad={"public class FloorPlanProxy(string address, bool canView) : IFloorPlan\n{\n    private ScannedFloorPlan? scan;\n\n    // anyone who reads Scan skips the check\n    public ScannedFloorPlan Scan => scan ??= new ScannedFloorPlan(address);\n\n    public string Render() =>\n        canView ? Scan.Render() : $\"Plans of {address} are not available\";\n}"}
  good={"public class FloorPlanProxy(string address, bool canView) : IFloorPlan\n{\n    private ScannedFloorPlan? scan;\n\n    private ScannedFloorPlan Scan => scan ??= new ScannedFloorPlan(address);\n\n    public string Render() =>\n        canView ? Scan.Render() : $\"Plans of {address} are not available\";\n}"}
  badLabel="the real object is public"
  goodLabel="only Render is public"
/>

</Pitfall>
