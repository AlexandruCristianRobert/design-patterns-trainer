<Section id="problem">

A running app has a `TrainingLog` that lists runs in kilometres, with the time of each as a `TimeSpan`. Now it should import runs from a watch. The watch maker ships <Role kind="concrete">PaceWatchSdk</Role>, a library the app cannot edit, and it speaks miles and seconds. The first version reaches straight into it:

<AnnotatedCode
  caption="The first version: the log speaks the SDK's language"
  code={`
public class TrainingLog(PaceWatchSdk watch)
{
    public void PrintRuns()
    {
        foreach (var a in watch.FetchActivities())
        {
            // The SDK speaks miles and seconds; the log wants km and a TimeSpan.
            var km = a.Miles * 1.609344;
            var duration = TimeSpan.FromSeconds(a.Seconds);
            Console.WriteLine($"{a.Day}: {km:F1} km in {duration}");
        }
    }
}
`}
  marks={[
    { line: 1, tone: 'bad', badge: '1' },
    { line: 5, tone: 'bad', badge: '2' },
    { line: 7, tone: 'bad' },
    { line: 8, tone: 'bad', badge: '3' },
    { line: 9, tone: 'bad' },
  ]}
/>

It prints the right numbers, and it <Key>makes the log depend on the watch</Key>:

<BadgeList tone="bad" count={3}>

1. The log is built around one maker's class. A second watch brand needs a second constructor and an `if` in the log for every brand.
2. The SDK's way of asking, `FetchActivities()` and its `Activity` values, spreads through the log.
3. The conversions live in the log, so every other place that reads runs has to repeat them, and one forgotten `* 1.609344` is a wrong distance.
4. The obvious fix, changing the SDK, is not possible, because the code belongs to the watch maker.

</BadgeList>

<KeyIdea>

The log should ask in its own words and never see the SDK. <Key>Put a small translator in between</Key>, so neither side has to change.

</KeyIdea>

</Section>

<Section id="analogy">

Think of a travel plug adapter. Your charger's plug will not fit the socket in another country, and you cannot rebuild either one. You put <Key>a small piece in between</Key>, with your plug's shape on one side and the socket's shape on the other.

The charger and the wall stay exactly as they were. The piece only makes them fit, and it does not charge anything itself.

Adapter has the same shape: the <Role kind="concrete">SDK</Role> is the plug, the code that expects <Role kind="contract">IRunSource</Role> is the socket, and the <Role kind="primary">adapter</Role> is the piece between them.

<Section id="example">

The example is the program from the scene. Run it and you should see two lines: `Mon: 5.0 km in 00:30:00` and `Wed: 10.0 km in 00:55:00`. Both started as miles and seconds inside the SDK.

Then change it. Add a second watch brand: a `StrideBandSdk` with a `ReadWorkouts()` method that returns metres and minutes, and a `StrideBandAdapter` that implements <Role kind="contract">IRunSource</Role> on top of it. Give the new adapter to the log. You should not need to change `TrainingLog`.

Notice that the log never names a watch class, and that only <Role kind="primary">PaceWatchAdapter</Role> mentions miles.

<Section id="when-to-use">

Use Adapter when:

<Checklist>
  <Verdict ok><span>a class does what you need but has <Key>the wrong interface</Key>, and you cannot change it because it is a library or old code;</span></Verdict>
  <Verdict ok><span>several classes with different interfaces should be used <Key>in the same way</Key>, such as one adapter per watch brand;</span></Verdict>
  <Verdict ok><span>you want the translation in one place, instead of repeated in every caller.</span></Verdict>
  <Verdict ok={false}><span>**Skip it** when you own both sides. Change one interface to fit the other, and you do not need a class that only hides the mismatch.</span></Verdict>
</Checklist>

### Holding the adaptee or inheriting from it

There are two ways to build the adapter. An object adapter holds the SDK and calls it. A class adapter inherits from the SDK and implements the contract on itself.

<Figure
  caption="Holding the SDK or inheriting from it"
  description="Two cards. An object adapter holds a PaceWatchSdk and calls it, which is composition. It works with any adaptee, even a sealed one, and C# favours it, so this is the good choice. A class adapter inherits from PaceWatchSdk and also implements IRunSource, which is inheritance. It needs an adaptee that is not sealed, and everything public on the SDK shows through the adapter, so it is the weaker choice."
>
<Row align="start">
  <Card title="Object adapter">
    <Stack>
      <Box role="primary" sub="implements IRunSource">
        {"PaceWatchAdapter"}
        <Box role="concrete" mono={false} sub="held in a field">PaceWatchSdk</Box>
      </Box>
      <Verdict ok>works with any adaptee, even a sealed one, and the SDK stays hidden</Verdict>
    </Stack>
  </Card>
  <Card title="Class adapter">
    <Stack>

  </Card>
</Row>

C# has single inheritance for classes, so the class adapter uses up its one base class on the adaptee. The example is an object adapter, and that is the usual choice.

### Pitfalls

<Pitfall title="An adapter that decides things">

An adapter that drops some runs or applies a rule has stopped translating. Each brand's adapter then makes its own decisions, and two watches give different results for the same runs. Convert everything, and let the log decide.

<CodePair
  bad={"public IReadOnlyList<Run> GetRuns() =>\n  sdk.FetchActivities()\n     .Where(a => a.Miles >= 3)   // a rule\n     .Select(Convert).ToList();"}
  good={"// The adapter converts every activity.\npublic IReadOnlyList<Run> GetRuns() =>\n  sdk.FetchActivities().Select(Convert).ToList();\n\n// The log decides what counts.\nvar counted = source.GetRuns().Where(r => r.Km >= 5);"}
  badLabel="the adapter filters"
  goodLabel="the log decides"
/>

</Pitfall>

<Pitfall title="Letting the SDK's types leak">

If the contract returns the SDK's own `Activity`, the log needs the SDK's types again and the adapter has protected nothing. The contract speaks only the log's types.

<CodePair
  bad={"public interface IRunSource\n{\n  List<Activity> GetRuns();   // the SDK's type\n}"}
  good={"public interface IRunSource\n{\n  IReadOnlyList<Run> GetRuns();   // the log's type\n}"}
  badLabel="SDK type in the contract"
  goodLabel="the log's own type"
/>

</Pitfall>
