<Section id="problem">

A wedding planner lays out the seating. One table gets set up carefully: a shape, a list of chairs, a centrepiece. To get ten more, the first version <Key>rebuilds each one by hand</Key>, with the setup pasted again, and it needs a branch for every kind of table:

<AnnotatedCode
  caption="The first version: paste the setup, test the class"
  code={`
var table1 = new RoundTable("lilies");
table1.AddChair("chair 1");
table1.AddChair("chair 2");
// Table 2: the same setup, pasted again
var table2 = new RoundTable("lilies");
table2.AddChair("chair 1");
table2.AddChair("chair 2");

ITable Duplicate(ITable table)
{
    if (table is RoundTable r) return new RoundTable(r.Centrepiece, new List<string>(r.Chairs));
    if (table is LongTable l) return new LongTable(l.Centrepiece, l.Metres, new List<string>(l.Chairs));
    throw new NotSupportedException();
}
`}
  marks={[
    { line: 5, tone: 'bad', badge: '1' },
    { line: 6, tone: 'bad' },
    { line: 7, tone: 'bad' },
    { line: 11, tone: 'bad', badge: '2' },
    { line: 12, tone: 'bad', badge: '3' },
  ]}
/>

It works, and it is hard to <Key>keep right</Key>:

<BadgeList tone="bad" count={3}>

1. The setup is pasted for every table. Ten tables are ten places where a forgotten chair can hide.
2. `Duplicate` has to name every concrete class, and read every field of each one from outside.
3. A new kind of table adds a new branch, and a new field means finding every copy of the setup.
4. The planner only wanted another table like that one, and ends up knowing how every kind of table is built.

</BadgeList>

<KeyIdea>

The configured table already knows everything about itself, so <Key>ask the table for a copy</Key> instead of rebuilding it from outside.

</KeyIdea>

</Section>

<Section id="analogy">

Think of the key cutter at a hardware shop. You do not tell them which lock maker made your lock or hand over a blueprint. You hand over <Key>the key itself</Key>, and the cutter makes a new one with the same shape.

The new key is a separate piece of metal. Bend it, and your original is fine.

Prototype has the same shape: the <Role kind="concrete">configured table</Role> is the key, and a copy comes from that object, not from a blueprint of its class.

The contract is <Role kind="contract">ITable</Role>, and its <Role kind="contract">Clone</Role> method returns a copy of the table. The client, <Role kind="primary">SeatingPlan</Role>, is handed a configured table and asks it for a copy. It never writes `new RoundTable(...)` and never checks which class it has. Hover or focus a box to see its code in the example.

<Section id="when-to-use">

Use Prototype when:

<Checklist>
  <Verdict ok><span>an object is <Key>fiddly to set up</Key>, and you want many more like one that is already configured;</span></Verdict>
  <Verdict ok><span>the code that needs a copy <Key>should not know the concrete class</Key> of what it copies;</span></Verdict>
  <Verdict ok><span>there are only a few configured starting points, and copying a template is easier than a subclass for each.</span></Verdict>
  <Verdict ok={false}><span>**Skip it** when the object is simple. A plain `new`, or a record with `with`, says the same thing with less ceremony.</span></Verdict>
</Checklist>

### Shallow or deep copy

The part to get right is what the copy shares with the original. A shallow copy copies the table's own fields, but a field that holds a list only copies the reference to it. A deep copy also copies what those fields point to.

<Figure
  caption="Shared chair list or a list of its own"
  description="Two cards. In a shallow copy, the original table and the copy both point to one shared chair list, so adding a chair to the copy also changes the original, which is wrong. In a deep copy, the original and the copy each hold their own chair list, so editing the copy leaves the original alone, which is right."
>
<Row align="start">
  <Card title="Shallow copy">
    <Stack>
      <Box role="concrete" mono={false}>original table</Box>
      <Box role="concrete" mono={false}>copy table</Box>
      <Arrow dir="down" label="both point to" />
      <Box tone="bad" mono={false}>one chair list</Box>
      <Verdict ok={false}>add a chair to the copy and the original gets it too</Verdict>
    </Stack>
  </Card>
  <Card title="Deep copy">
    <Stack>
      <Box role="concrete" mono={false} sub="original">
        <Box tone="ok" mono={false}>chair list</Box>
      </Box>
      <Box role="concrete" mono={false} sub="copy">
        <Box tone="ok" mono={false}>chair list</Box>
      </Box>
      <Verdict ok>the copy has its own list, so the original stays as it was</Verdict>
    </Stack>
  </Card>
</Row>
</Figure>

Whichever you choose, make it a decision. A table that only holds strings and numbers can be copied shallowly, and one that holds a list needs the list copied too.

### What .NET gives you

Three things in C# look like Prototype. None of them is deep by itself.

>

So write your own typed `Clone()` as the example does, and say in the method which kind of copy it makes. `MemberwiseClone` copies every field as it is, so it only suits a class with no list fields, or one whose list fields are not `readonly` so that the copy can be given new lists.

### Pitfalls

<Pitfall title="A shallow copy that shares the list">

If `Clone()` is just `MemberwiseClone()`, the copy and the original share one chair list, and a change to either shows up in both. Copy the list as well.

<CodePair
  bad={"public ITable Clone() =>\n  (ITable)MemberwiseClone();"}
  good={"public ITable Clone()\n{\n  var copy = new RoundTable(centrepiece);\n  foreach (var chair in chairs) copy.AddChair(chair);\n  return copy;\n}"}
  badLabel="shares the list"
  goodLabel="list of its own"
/>

</Pitfall>

<Pitfall title="Relying on ICloneable">

`ICloneable.Clone()` returns `object` and does not say whether the copy is shallow or deep, so every caller has to guess and cast. Declare your own `Clone()` on the contract, with the right return type.

<CodePair
  bad={"var copy = (RoundTable)template.Clone();\n// shallow or deep? the type does not say"}
  good={"ITable copy = template.Clone();\n// the contract promises a deep copy"}
  badLabel="object, then a cast"
  goodLabel="typed, and stated"
/>

</Pitfall>

<Pitfall title="A copy that is still the original in disguise">

If a table has a number that must be unique, a copy that keeps the original's number gives you two tables with the same number. Anything that should differ must be set again on the copy.

<CodePair
  bad={"var copy = template.Clone();\n// copy.Number is still the template's"}
  good={"var copy = template.Clone();\ncopy.Number = nextNumber++;"}
  badLabel="same number twice"
  goodLabel="its own number"
/>

</Pitfall>
