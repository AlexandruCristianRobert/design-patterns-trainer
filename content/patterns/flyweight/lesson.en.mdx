<Section id="problem">

A concert hall's booking page draws a seat map of 40,000 seats, in five price bands: gold, red, blue, green and grey. The first version gives every seat everything it needs to draw itself, and each seat loads that for itself:

<AnnotatedCode
  caption="The first version: every seat carries its own style"
  code={`
public class Seat(int row, int number, string band)
{
    public int Row = row;
    public int Number = number;
    public string Colour = File.ReadAllText($"bands/{band}.colour");
    public byte[] Icon = File.ReadAllBytes($"bands/{band}.png");
    public string LabelFont = File.ReadAllText($"bands/{band}.font");
    public string Description = File.ReadAllText($"bands/{band}.txt");
}

string[] bands = ["gold", "red", "blue", "green", "grey"];
var hall = new List<Seat>();
for (var row = 1; row <= 200; row++)
    for (var number = 1; number <= 200; number++)
        hall.Add(new Seat(row, number, bands[row % 5]));
`}
  marks={[
    { line: 5, tone: 'bad', badge: '1' },
    { line: 6, tone: 'bad' },
    { line: 7, tone: 'bad' },
    { line: 8, tone: 'bad', badge: '2' },
    { line: 15, tone: 'bad', badge: '3' },
  ]}
/>

It draws the right map, but <Key>every seat holds its own copy of data that has only five different values</Key>. A seat's row and number are its own. The other four fields are the same for every seat in its band:

<BadgeList tone="bad" count={3}>

1. Each seat holds its own colour, icon, font and description. The 8,000 gold seats each read and keep their own gold icon and gold text, and they are the same every time.
2. Memory grows with the number of seats, not the number of bands. As an estimate, if the icon and the text come to about 5 KB for a seat, the hall holds about 200 MB of copies (40,000 × 5 KB).
3. Changing a band means touching every seat in it. A new colour for gold has to be written into 8,000 seats, and a seat that was missed keeps the old colour.
4. Opening the hall reads four files for each seat, which is 160,000 reads, to get the same five sets of answers.

</BadgeList>

<KeyIdea>

A seat is two things: where it is, which is its own, and what it looks like, which belongs to its band. Store the look once for each band.

</KeyIdea>

</Section>

The **flyweight** is <Role kind="primary">SeatStyle</Role>. It holds what every seat of a band has in common: the band's name, colour and icon. It is a sealed `record` whose properties can only be set when it is created, so it cannot change afterwards, and that is what makes it safe to share. It never holds a row or a number.

The **flyweight factory** is <Role kind="concrete">SeatStyleCatalog</Role>. Its `Get(band)` returns the style for a band, and makes it only the first time. Everything depends on this: if some code builds a `SeatStyle` itself, the sharing has a hole in it.

The per-seat data is <Role kind="concrete">SeatSpot</Role>: a row, a number and a reference to a style. It is a `readonly record struct`, a value type, so the list holds the spots directly, with no extra object for each one. The client is <Role kind="concrete">SeatMap</Role>. It holds the spots, and asks the catalog for a style whenever it adds a seat.

Because a `record` compares by value, `==` on two styles can be true for two different objects. To check that two seats share one style, use `ReferenceEquals`, as the example does.

<Section id="example">

The example is the program from the scene, with 5 rows of 8 seats, which is 40 seats in five bands. Run it and you should see four lines: `Seats: 40`, `Styles created: 5`, `Seats 1 and 2 share one style: True` and `Row 1 seat 1 is gold`. Forty seats were added, and only five styles were ever made.

Then change it. Add a wheelchair band. Give `SeatStyleCatalog` one more entry in its table of bands, for `"wheelchair"` with a colour and an icon, and add one seat with `map.AddSeat(6, 1, "wheelchair");` before the lines that print. You should see `Seats: 41` and `Styles created: 6`. <Key>A new band is one new table entry</Key>: <Role kind="concrete">SeatMap</Role>, <Role kind="concrete">SeatSpot</Role> and <Role kind="primary">SeatStyle</Role> need no change.

<Section id="when-to-use">

Use Flyweight when:

<Checklist>
  <Verdict ok><span>you have <Key>a very large number of similar objects</Key>, and memory or load time is a real problem (measure it first);</span></Verdict>
  <Verdict ok><span>most of what each object holds is <Key>the same for many of them</Key>, so it can be split into a shared part and a small own part;</span></Verdict>
  <Verdict ok><span>the shared part can be <Key>immutable</Key>, and the own part can be passed in or kept in a small value.</span></Verdict>
  <Verdict ok={false}><span>**Skip it** when there are few objects, or when each one differs. Sharing a handful of objects saves nothing, and it adds a catalog and a split to keep in mind.</span></Verdict>
</Checklist>

### Shared or passed in

The split has two names. <Key>Intrinsic</Key> state is what an object is, independent of where it is used, and it can be shared. <Key>Extrinsic</Key> state is what depends on the use, and it is passed in or stored outside the shared object.

### A flyweight you already use

<Note icon="lightbulb">

In .NET, strings are flyweights. A string is immutable, so equal strings can safely be one object. Literals in your code are interned automatically: `ReferenceEquals("gold", "gold")` is true. A string built at run time is not interned by itself, but `string.Intern(text)` returns the shared copy, and that is a catalog, too.

</Note>

### Pitfalls

<Pitfall title="A flyweight that can change">

A shared object is one object, so a change made through one seat is a change for all of them. If <Role kind="primary">SeatStyle</Role> has a setter, marking one seat as sold by changing its colour turns the whole band that colour. Make the shared part immutable. A seat that needs a different look gets a different style from <Role kind="concrete">SeatStyleCatalog</Role>.

<CodePair
  bad={"public class SeatStyle(string band, string colour)\n{\n    public string Colour { get; set; } = colour;\n}\n\n// Mark seat 1 as sold:\nspots[0].Style.Colour = \"#888888\";   // every gold seat turns grey"}
  good={"public sealed record SeatStyle(string Band, string Colour, string Icon);\n\n// Mark seat 1 as sold: give it another style.\nspots[0] = spots[0] with { Style = catalog.Get(\"grey\") };"}
  badLabel="the shared style can change"
  goodLabel="the style is immutable"
/>

</Pitfall>
