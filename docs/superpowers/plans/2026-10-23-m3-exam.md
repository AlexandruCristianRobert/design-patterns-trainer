# M3 · Exam Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A learner sets up an Exam (count, scope, Named mode, timer), writes real C# for each Exam Question with the book closed, identifies each Pattern, submits (or is auto-submitted when time runs out), and reads an Exam Report. The score feeds the Catalog's best exam %, and the session appears in the Progress page's exam history. This all works with Observer's 3 Exam Questions.

**Architecture:**
- Exam Questions are content files beside each Pattern's Exercises. They load the same way and are validated by the same .NET validator.
- The exam domain is pure TypeScript and fully unit-tested: question selection, scoring and deadlines.
- Exam Sessions live in a new IndexedDB store. Grading reuses the M2 `gradeExercise` orchestration, run once per question at submit.
- There are three new routes on top of the existing `CodePanel`, `ContractView` and `CheckList`. One app-level watcher auto-submits an expired session wherever the learner is in the app.

**Tech Stack:** the M2 stack. No new runtime dependencies. Playwright `page.clock` is used for timer tests.

**Spec:** `docs/superpowers/specs/2026-10-22-design-patterns-trainer-design.md`. This plan covers milestone M3: §6 Exam, §7 Progress (best exam score, exam history), §8 UI (`/exam`, `/exam/:sessionId`, `/exam/:sessionId/report`, 390 px rule for Exam Reports) and §3 (Exam Questions, Lookalikes). Also read `CONTEXT.md` for the vocabulary (Exam Question, Exam Session, Exam Report, Identification, Named mode), `DESIGN.md`, and the M2 code on `main`.

## Global Constraints

- Everything from the M1 and M2 Global Constraints still binds:
  - i18next for all UI copy, one namespace per area
  - `DESIGN.md` tokens
  - invoke `uxkin:no-ui-slop` before any UI work
  - Lucide icons only, no emoji
  - Exercise statuses and Drafts behave as in M2
  - commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
- Exam Question count per Tier: Standard = 3, Tricky = 5. Observer is Standard, so it has 3. Each question uses a different domain, and none reuses an Exercise's or the Lesson example's domain.
- Exam setup defaults:
  - count 1–10, default 3
  - scope: all, chosen Categories or chosen Patterns; default all
  - Named mode off
  - timer on, 15 min × question count
- During a session the book is closed:
  - no Hints, solutions, Lessons or Check results on the session page
  - Run is allowed (compiler errors and console output)
  - free navigation between questions
  - auto-submit when the timer expires
- Selection: no Pattern appears twice in a session unless the count exceeds the number of Patterns in scope. Least-recently-seen Exam Questions come first. A question never repeats within a session.
- Identification offers all 23 GoF names, whether or not they are built.
- Scoring per question:
  - Identification 20% + Checks 80% × (passed ÷ total)
  - in Named mode, Checks 100%
  - the session score is the mean of the question scores
  - pass mark is `0.7`, and a session passes when its score is ≥ 70%
- Interruption:
  - an in-progress session is saved continuously (answers debounced 500 ms)
  - on return, offer Resume or Abandon
  - the timer runs on wall-clock time
  - an expired session is auto-submitted on return
  - at most one session is in progress at a time
  - abandoned sessions are logged without a score
- In unnamed questions the Contract never names Pattern roles, and the scenario never names the Pattern.

## Rulings made in this plan

1. **Files and Pattern listing.** Exam Question files are `content/patterns/<id>/exam/<question-id>/{question.yaml, text.en.yaml, solution.cs, checks.cs}`, as in spec §3. `pattern.yaml` gains two fields:
   - `examQuestions: string[]`, the list of question ids
   - `roleNames: string[]`, the words an unnamed Contract or scenario must not contain

   Both default to `[]`.
2. **No starter file.** Exam Questions have no starter. Every question opens with the shared `EXAM_STARTER` (`// Write your solution here.\n`). That code is English-only, as all C# is.
3. **Best exam score per Pattern.** It is the highest question score that Pattern has earned in any submitted session. The session score is what the history and pass/fail show.
4. **Auto-submit.** One watcher, mounted in `Shell`, auto-submits an expired in-progress session on any route, both on app start and while open. A module-level lock makes sure a session is graded once.
5. **Closed book.** It is enforced by the session page offering nothing, not by locking the rest of the app: nothing is locked. While a session is in progress, a shell banner shows the time left and a "Return to exam" link.
6. **Grading failures.** If grading a question throws (a content bug, or a runner crash or timeout during load), that question scores 0 for Checks. The report shows "The checks couldn't run for this answer".
7. **Comparing check ids.** `gradeExercise` compares the discovered check ids with the **`en`** text's check keys, not the localized text's. This fixes the M2 parked translation risk.
8. **Export and import.**
   - Export is `schemaVersion: 2` and adds `examSessions`.
   - Import accepts versions 1 and 2. Importing either replaces all three stores, so a v1 import clears exam history.
   - `ImportResult.ok` gains `exams: number`.

## Review Focus

1. **Timer and interruption.** The learner closes the tab mid-exam and returns after the deadline. The session must be auto-submitted with every saved answer and graded, and it must land on the report. Returning before the deadline must offer Resume with the wall-clock time left. Tests: watcher test in Task 7, e2e with `page.clock` in Task 11.
2. **Lost answers.** A reload mid-exam must restore the code and the Identification for every question. Tests: session page test in Task 8, e2e in Task 11.
3. **Double grading.** The timer fires while the learner presses Submit, or two tabs submit. There must be exactly one submitted result, graded once. Tests: `finishSession` only acts on in-progress sessions (Task 5); the submit lock test (Task 6).
4. **Thin scope.** The scope holds fewer questions than the chosen count, or none at all. The setup must cap the count with a note, or disable Start with an explanation; it must never start an empty session. Tests: selection tests (Task 4), setup page test (Task 7).
5. **Leaking the answer.** In unnamed mode, the Contract type and member names, the question title and the scenario must not give away the Pattern. Tests: validator rule with fixtures (Task 2). The session page test asserts that the Pattern name appears only in Named mode (Task 8).

### Task 4: Exam domain: selection, scoring, deadline

**Files:**
- Create: `web/src/exam/{types.ts, selection.ts, scoring.ts, deadline.ts}` + `selection.test.ts`, `scoring.test.ts`, `deadline.test.ts`

**Interfaces:**
- Produces:
  ```ts
  // types.ts
  export type ExamScope = { kind: 'all' } | { kind: 'categories'; categories: Category[] } | { kind: 'patterns'; patternIds: string[] }
  export interface ExamSetup { count: number; scope: ExamScope; named: boolean; timed: boolean }
  export interface ExamAnswer { code: string; identification: string | null }   // pattern id or null
  export type QuestionGrade =
    | { kind: 'checked'; results: CheckResult[] } | { kind: 'compileErrors'; diagnostics: DiagnosticInfo[] }
    | { kind: 'contractViolations'; violations: ContractViolation[] } | { kind: 'error' }
  export interface QuestionResult { questionKey: string; patternId: string; identification: string | null;
    identifiedCorrectly: boolean | null /* null in Named mode */; grade: QuestionGrade;
    checksPassed: number; checksTotal: number; score: number /* 0..1 */ }
  export type ExamStatus = 'inProgress' | 'submitted' | 'abandoned'
  export interface ExamSession { id: string; status: ExamStatus; setup: ExamSetup; questionKeys: string[];
    startedAt: string; deadline: string | null; answers: Record<string, ExamAnswer>;
    endedAt?: string; submittedBy?: 'learner' | 'timer'; results?: QuestionResult[]; score?: number; passed?: boolean }
  // selection.ts
  export function scopePatternIds(scope: ExamScope, pool: ExamQuestionContent[]): Set<string>
  export function availableCount(setup: Pick<ExamSetup, 'scope'>, pool: ExamQuestionContent[]): number
  export function selectQuestions(pool: ExamQuestionContent[], setup: ExamSetup,
    lastSeen: Record<string, string>, random: () => number): string[]   // question keys, length = min(count, available)
  // scoring.ts
  export const PASS_MARK = 0.7
  export function questionScore(named: boolean, identifiedCorrectly: boolean, passed: number, total: number): number
  export function sessionScore(scores: number[]): number      // mean; 0 for []
  export function isPass(score: number): boolean              // score >= PASS_MARK - 1e-9
  // deadline.ts
  export const MINUTES_PER_QUESTION = 15
  export function deadlineFor(startedAt: string, setup: ExamSetup, questionCount: number): string | null
  export function remainingMs(session: Pick<ExamSession, 'deadline'>, now: number): number | null   // never negative
  export function isExpired(session: Pick<ExamSession, 'status' | 'deadline'>, now: number): boolean
  ```

Selection algorithm:
1. Filter the pool to the scope.
2. Sort by `lastSeen` ascending. Never-seen questions come first, and ties are broken with `random`.
3. In the first pass, take at most one question per Pattern, in sorted order, until `count` is reached.
4. If more questions are needed, later passes take further unused questions in the same order. A question is never repeated.
